# 按需模块（Modules）

> 按需加载，命中对应场景时才加载本文件。所有模块均服从 `No Spec, No Code` 与 `No Approval, No Execute`。

---

## Deep Planning（深度规划）

**适用场景**：需求模糊、架构设计、跨模块重构、迁移、长链路任务。

**执行要点**：
- 先收敛目标、边界、约束，并写回 spec。
- 模型先用自己的话复述任务理解，确认核心目标一致。
- 必要时提供 2-3 个方案并说明取舍。
- 计划要短但必须覆盖：`files`（文件）、`interfaces`（接口）、`order`（顺序）、`risks`（风险）、`validation`（验证）。
- 重点不是展开阶段，而是做一次足够清晰的 checkpoint summary。
- 输出 summary/plan 后**必须暂停**，等待用户批准后才进入实现。

---

## Debug（调试）

**适用场景**：报错复现不稳定、根因未知、链路过长、怀疑多处共同导致。

**执行要点**：
- 遵循流程：先复现 → 缩小范围 → 形成假设 → 验证，**绝不盲改**。
- 每轮排查前重申当前要验证的核心问题，避免思路漂移。
- 优先收集最有区分度的日志、调用链、输入条件。
- 将根因假设、排查结论、拟议修法写入 spec，再请求执行批准。
- 若需临时探针或额外日志，控制在最小范围，收尾时必须清理或说明。
- 结论至少回答三个问题：`根因是什么`、`为什么现在修法有效`、`还有什么未覆盖`。

## Review（评审）

**适用场景**：用户要求评审、任务收尾、风险较高的改动、准备提交前。

**评估维度**（默认从4点快速评估）：
- `Completion`：目标是否达成。
- `Fidelity`：实现是否偏离 spec / 当前 checkpoint。
- `Quality`：代码正确性、可维护性、测试/验证是否足够。
- `Risk`：残余风险、回归点、后续建议。

**执行要点**：
- 优先检查：最终实现是否仍然对齐最初复述的核心目标。
- 输出保持简短，结论反向同步到 spec；只有高风险时才展开说明。

---

## Multi-project（多项目协同）

**适用场景**：多仓、monorepo、前后端联动、跨子项目任务。

**执行要点**：
- 先声明 `active_project` 与当前改动范围，并写入 spec。
- 先复述跨项目任务的核心目标和边界，再决定是否进入 `cross` 状态。
- 默认处于 `local` 状态，仅在任务明确需要时扩展到 `cross`。
- 跨项目时需记录：改了哪些项目、接口如何对齐、依赖顺序是什么。
- 切换项目或进入跨项目实现前，需回读该项目相关 spec / codemap 区块。
- 跨项目 checkpoint 获批后再执行。
