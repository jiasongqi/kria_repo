# 重构优化规范 — refactor.md
> 当你需要重构代码、提取公共逻辑、优化性能时，加载本文件。

---

## ⚠️ 重构前提条件（必须全部满足）

- [ ] **用户明确要求重构** — 不主动重构用户未提及的代码
- [ ] **有测试保障** — 重构前确认核心逻辑有测试覆盖（或手动验证路径）
- [ ] **范围已明确** — 知道改哪里、不改哪里
- [ ] **不混入新功能** — 重构和新功能分开提交，不在同一次修改中混做

---

## 🪜 安全重构步骤

```
Step 1: 读懂现有代码
         → 理解每一行的意图，不要边读边改
         → 标记哪些是"可以动的"，哪些是"绝对不能动的"

Step 2: 最小化改动
         → 只提取/移动代码，不改逻辑
         → 保持对外接口不变（方法签名、返回值）

Step 3: 逐步验证
         → 每改一小步就验证一次
         → 不要一次性大改后再测试

Step 4: 提交
         → 重构用独立 commit，type 用 refactor
         → commit message 说清楚"把 X 提取到 Y"
```

## ✅ 常见重构场景

### 提取方法
**触发条件**：一个方法超过 50 行，或同一逻辑出现 2 次以上

```java
// Before: 逻辑堆在一起
public void processOrder(Order order) {
    // 校验逻辑（20行）
    // 计算逻辑（30行）
    // 保存逻辑（20行）
}

// After: 职责单一
public void processOrder(Order order) {
    validateOrder(order);
    calculateAmount(order);
    saveOrder(order);
}
```

### 消除重复代码
**触发条件**：相同逻辑在 2 个以上地方出现

- 提取到 `utils/` 工具类
- 提取到 `common/` 公共服务
- 使用继承/组合复用

### 简化条件判断
**触发条件**：if-else 超过 3 层嵌套

```java
// Before: 深层嵌套
if (a) {
    if (b) {
        if (c) { doSomething(); }
    }
}

// After: 提前返回（卫语句）
if (!a) return;
if (!b) return;
if (!c) return;
doSomething();
```

### 常量替换魔法值
**触发条件**：代码中出现无意义的数字或字符串

```java
// Before
if (status == 2) { ... }

// After
private static final int STATUS_APPROVED = 2;
if (status == STATUS_APPROVED) { ... }
```

## 🚀 性能优化规范

### 数据库查询优化
- [ ] 避免 N+1：循环内不查库，改用批量查询 + Map 映射
- [ ] 检查索引：用 `EXPLAIN` 确认查询命中索引
- [ ] 分页查询：大数据量必须分页，禁止全量加载
- [ ] 只查需要的字段：避免 `SELECT *`

### 缓存使用规范
- [ ] 缓存 key 命名规范：`业务:对象:ID`，如 `user:info:123`
- [ ] 设置合理的过期时间，避免永不过期
- [ ] 更新数据时同步清除/更新缓存
- [ ] 热点数据考虑本地缓存（避免频繁 Redis 调用）

### Java 性能注意点
- [ ] 字符串拼接用 `StringBuilder`，不用 `+` 循环拼接
- [ ] 集合初始化时指定容量，避免频繁扩容
- [ ] 流处理（Stream）避免嵌套，考虑并行流的适用场景
- [ ] 避免在循环中创建大对象

## 📊 重构前后对比模板

```
## 重构说明

**重构原因**：xxx 方法过长（X行）/ 重复代码出现 X 处 / ...

**改动范围**：
- 修改文件：xxx
- 不影响范围：xxx（接口不变/外部调用不变）

**重构内容**：
- 提取 xxx 方法到 xxx
- 消除 xxx 处重复逻辑

**验证方式**：
- [ ] 原有功能手动验证通过
- [ ] 单测运行通过
```

## 🚫 重构禁忌

- ❌ 重构时顺带修复 bug 或加新功能（分开做）
- ❌ 修改对外的方法签名（破坏调用方）
- ❌ 没有任何验证就提交重构
- ❌ 用户没要求重构，主动大幅重写
- ❌ 一次重构改动超过 5 个文件（应拆分多次）
