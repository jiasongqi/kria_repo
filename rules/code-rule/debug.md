# Debug 排查规范 — debug.md
> 当你需要排查 Bug、分析异常日志、定位问题原因时，加载本文件。

---

## 🔎 排查流程（按顺序执行）

```
Step 1: 复现问题
         → 明确触发条件：什么操作 + 什么数据 + 什么环境
         → 能稳定复现才开始排查

Step 2: 收集信息
         → 完整的错误日志（带堆栈）
         → 问题发生的时间节点
         → 最近一次有效的代码/配置变更

Step 3: 缩小范围
         → 二分法定位：哪一层出的问题（前端/网关/服务/数据库）
         → 看日志中第一个异常（不是最后一个）

Step 4: 定位根因
         → 找到具体的代码行
         → 理解为什么会走到这里

Step 5: 修复 + 验证
         → 最小化修改，只改导致 bug 的地方
         → 验证修复后原场景正常 + 关联场景不受影响

Step 6: 总结
         → 记录：根因 + 修复方式 + 如何预防
```

## 📋 常见问题排查清单

### 接口报错
- [ ] 查看完整堆栈（不要只看最后一行）
- [ ] 检查请求参数是否符合预期
- [ ] 检查数据库中数据状态
- [ ] 检查外部依赖（第三方接口/缓存/MQ）是否正常
- [ ] 检查配置文件是否加载正确

### NullPointerException
- [ ] 找到第一个 null 的来源
- [ ] 检查 Optional 是否正确使用
- [ ] 检查数据库查询结果是否判空
- [ ] 检查集合/列表遍历前是否判空

### 数据不一致
- [ ] 检查事务边界（是否在同一事务内）
- [ ] 检查并发写入（是否有锁）
- [ ] 检查缓存是否过期/未更新
- [ ] 检查是否有多个服务节点写入同一数据

### 性能问题
- [ ] 查看慢查询日志
- [ ] 检查是否有 N+1 查询（循环内查数据库）
- [ ] 检查索引是否命中（EXPLAIN）
- [ ] 检查是否有不必要的全量数据加载

## 🪵 日志分析技巧

```bash
# 按时间段过滤日志
grep "2026-04-02 10:" app.log

# 找 ERROR 级别
grep -n "ERROR" app.log | head -50

# 找特定请求 ID（链路追踪）
grep "traceId=abc123" app.log

# 找异常堆栈（取异常后 20 行上下文）
grep -A 20 "Exception" app.log
```

## 🔁 复盘模板

```
## Bug 复盘

**现象**：xxx 功能在 xxx 条件下出现 xxx 错误

**根因**：xxx 处理逻辑未考虑 xxx 场景，导致 xxx

**修复**：在 xxx 处增加 xxx 判断/处理

**预防**：
- [ ] 增加单测覆盖此场景
- [ ] 增加监控告警
- [ ] 补充代码注释说明边界条件
```

---

## 🚫 排查禁忌

- ❌ 没有复现就开始修改代码
- ❌ 只看最后一个异常，忽略根因异常
- ❌ 修复时顺便"优化"无关代码
- ❌ 修复后不验证关联场景
