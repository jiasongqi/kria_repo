# 代码审查标准

> 当你需要做 Code Review、审查他人代码、或被要求检查代码质量时，加载本文件。

## 目的

代码审查确保代码合并前的质量、安全性和可维护性。此规则定义何时以及如何进行代码审查。

## 何时审查

**强制审查触发条件：**

- 编写或修改代码后
- 提交到共享分支之前
- 更改安全敏感代码时（认证、支付、用户数据）
- 进行架构更改时
- 合并 pull request 之前

**审查前要求：**

在请求审查之前，确保：

- 所有自动化检查（CI/CD）已通过
- 合并冲突已解决
- 分支已与目标分支同步

## 审查维度

按优先级从高到低：

### 🔴 P0 — 必须修复（阻断合并）
- [ ] **逻辑正确性** — 功能是否符合需求，边界条件是否处理
- [ ] **安全问题** — SQL 注入、XSS、越权访问、敏感信息暴露
- [ ] **数据一致性** — 事务边界是否正确，并发场景是否考虑
- [ ] **空指针/异常** — 未处理的 null、未捕获的异常

### 🟡 P1 — 建议修复（可合并但需跟进）
- [ ] **性能问题** — N+1 查询、无索引的大表查询、不必要的全量加载
- [ ] **代码可读性** — 命名是否清晰，逻辑是否易理解
- [ ] **重复代码** — 是否有可以抽取复用的逻辑
- [ ] **错误处理** — 异常是否有合理的处理和日志

### 🟢 P2 — 建议优化（可选）
- [ ] **注释** — 复杂逻辑是否有说明
- [ ] **测试覆盖** — 关键逻辑是否有单测
- [ ] **代码风格** — 是否符合团队规范

## 审查检查清单

在标记代码完成之前：

- [ ] 代码可读且命名良好
- [ ] 函数聚焦（<50 行）
- [ ] 文件内聚（<800 行）
- [ ] 无深层嵌套（>4 层）
- [ ] 错误显式处理
- [ ] 无硬编码密钥或凭据
- [ ] 无 console.log 或调试语句
- [ ] 新功能有测试
- [ ] 测试覆盖率满足 80% 最低要求

快速版：

```
□ 功能逻辑是否正确？
□ 是否有明显的安全漏洞？
□ 事务/并发是否处理正确？
□ 是否有 NPE 风险？
□ 是否有性能隐患（N+1、全表扫）？
□ 命名是否语义清晰？
□ 是否有大量重复代码？
□ 异常处理是否合理？
```

## 评审话术规范

**提问式（推荐）**
> "这里为什么选择 X 而不是 Y？"
> "这个场景下如果 XX 为空会怎样？"

**建议式**
> "建议提取成公共方法，后续复用更方便"
> "P1: 这里可能存在 N+1 查询，可以考虑批量查询"

**必须修复**
> "P0: 这里缺少权限校验，任意用户可访问他人数据，需要修复后才能合并"

## 审查禁忌

- ❌ 人身攻击，评论针对人不针对代码
- ❌ 只说"有问题"不说哪里有问题
- ❌ 把个人风格偏好当 P0 问题强制要求
- ❌ 审查范围外的代码大改（除非发现严重 bug）

## 审查总结模板

```
## ✅ 审查总结

- 本次审查文件数：X
- 严重问题：X 个
- 警告：X 个
- 建议：X 个
- 整体评价：一句话总结

## 约束

**必须改**（合并前解决）：
1. [P0] xxx 文件 xxx 行：问题描述

**建议改**（可跟进）：
1. [P1] xxx 文件：建议描述
```

## 安全审查触发条件

**停止并使用 security-reviewer 代理当：**

- 认证或授权代码
- 用户输入处理
- 数据库查询
- 文件系统操作
- 外部 API 调用
- 加密操作
- 支付或金融代码

## 审查严重级别

| 级别 | 对应 | 含义 | 行动 |
|-------|------|---------|--------|
| CRITICAL（关键） | P0 | 安全漏洞或数据丢失风险 | **阻止** - 合并前必须修复 |
| HIGH（高） | P1 | Bug 或重大质量问题 | **警告** - 合并前应修复 |
| MEDIUM（中） | P1/P2 | 可维护性问题 | **信息** - 考虑修复 |
| LOW（低） | P2 | 风格或次要建议 | **注意** - 可选 |

## 代理使用

使用这些代理进行代码审查：

| 代理 | 用途 |
|-------|--------|
| **code-reviewer** | 通用代码质量、模式、最佳实践 |
| **security-reviewer** | 安全漏洞、OWASP Top 10 |
| **java-reviewer** | Java / Spring Boot 特定问题 |
| **typescript-reviewer** | TypeScript/JavaScript 特定问题 |
| **python-reviewer** | Python 特定问题 |
| **go-reviewer** | Go 特定问题 |
| **rust-reviewer** | Rust 特定问题 |

## 审查工作流

```
1. 运行 git diff 了解更改
2. 先检查安全检查清单
3. 审查代码质量检查清单
4. 运行相关测试
5. 验证覆盖率 >= 80%
6. 使用适当的代理进行详细审查
```

## 常见问题捕获

### 安全

- 硬编码凭据（API 密钥、密码、令牌）
- SQL 注入（查询中的字符串拼接）
- XSS 漏洞（未转义的用户输入）
- 路径遍历（未净化的文件路径）
- CSRF 保护缺失
- 认证绕过

### 代码质量

- 大函数（>50 行）- 拆分为更小的
- 大文件（>800 行）- 提取模块
- 深层嵌套（>4 层）- 使用提前返回
- 缺少错误处理 - 显式处理
- 变更模式 - 优先使用不可变操作
- 缺少测试 - 添加测试覆盖

### 性能

- N+1 查询 - 使用 JOIN 或批处理
- 缺少分页 - 给查询添加 LIMIT
- 无界查询 - 添加约束
- 缺少缓存 - 缓存昂贵操作

## 批准标准

- **批准**：无关键或高优先级问题
- **警告**：仅有高优先级问题（谨慎合并）
- **阻止**：发现关键问题
